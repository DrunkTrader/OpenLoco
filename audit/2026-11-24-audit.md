## Overview

OpenLoco is an open-source reimplementation of Chris Sawyer's Locomotion (2004), written in modern C++20. The codebase totals ~235k lines across 12 modules under `src/`, with the monolithic `src/OpenLoco` module (~231k lines, 412 `.cpp` / 404 `.h`) dominating over the extracted libraries (Core, Engine, Utility, Math, Diagnostics, Gfx, Platform, Audio, Resources, Version). The build uses CMake 3.22+ with vcpkg for dependency management, targets Windows/Linux/macOS, and enforces clang-format + clang-tidy in CI.

This audit covers all ten requested lenses. Every finding is grounded in inspected code with file/function/line references.

## 1. Architecture

### Current Architecture

- **Intended layering:** Core/Diagnostics/Math/Utility/Gfx → Engine → OpenLoco → App (per `src/CMakeLists.txt` and each module's `PUBLIC_LINK_LIBRARIES`)
- **Actual state:** `src/OpenLoco` still contains UI, Input, Localisation, Graphics/Paint, and Game logic that conceptually belong in `Engine`. The TODO in `src/Engine/include/OpenLoco/Engine/Input/ShortcutManager.h:10` explicitly calls this out: `// TODO: Remove this when Localisation/StringTable/StringManager is moved to the engine.`
- **Dependency graph:** `src/OpenLoco/CMakeLists.txt:740-759` shows OpenLoco links *everything* (Audio, Core, Diagnostics, Platform, Utility, Math, Engine, Version, SDL3, yaml-cpp, PNG, ZLIB, TBB conditionally). This violates layering — OpenLoco should not need Math/Gfx/Diagnostics directly if Engine abstracts them.
- **Module granularity:** Good for Core/Math/Utility/Diagnostics/Gfx/Platform/Audio/Version/Resources. Engine is too thin (only 389 lines vs 231k in OpenLoco). App is minimal (354 lines).
- **Plugin/extensibility:** No plugin system; object data loaded from original game assets only.

### Problems

| Priority | Problem | Why It Matters | Suggested Solution | Files/Modules | Complexity |
|---|---|---|---|---|---|
| P1 | OpenLoco violates intended layering | Tight coupling prevents Engine from being reusable; circular deps risk | Move UI, Input, Localisation, Graphics/Paint, GameCommands into Engine; make OpenLoco thin glue | `src/Engine/`, `src/OpenLoco/` | High |
| P2 | `Engine` namespace polluted by `StringId` alias | `ShortcutManager.h:10` redefines `StringId = uint16_t` locally because StringManager not in Engine | Move StringManager/StringIds to Engine; remove local alias | `src/Engine/`, `src/OpenLoco/Localisation/` | Medium |
| P2 | No public API boundary | Everything in OpenLoco is private; no stable C ABI for tooling/mods | Define explicit public interface headers; hide internals | `src/OpenLoco/include/` | Medium |
| P3 | `App` and `Resources` separate but tiny | Over-fragmentation for 354 + 16 lines | Could merge into OpenLoco or keep for Windows resource build | `src/App/`, `src/Resources/` | Low |

## 2. Code Quality

### Duplicated/Dead Code

- **Window widget boilerplate:** 50+ window `.cpp` files each manually construct `std::array<Widget, N>` with repetitive `makeWidget()` calls (e.g., `src/OpenLoco/src/Ui/Windows/Vehicle.cpp:5284`, `Options.cpp:2968`). No code generation or declarative UI.
- **Object loading:** `src/OpenLoco/src/Objects/ObjectManager.cpp` has 30+ nearly-identical `load<Type>Object()` functions differing only in type and max count.
- **GameCommand handlers:** `src/OpenLoco/src/GameCommands/` has 90+ files, many <50 lines, each with identical boilerplate (`doCommand`, `registers` setup).

### Overly Complex Functions

| File | Function | Lines | Issue |
|---|---|---|---|
| `src/OpenLoco/src/World/CompanyAi/CompanyAi.cpp` | `sub_487144`, `aiThinkState0` | 7.8k total | Multiple 200+ line functions; `sub_` prefix from decompilation |
| `src/OpenLoco/src/Vehicles/VehicleHead.cpp` | `sub_4A8DB7`, `sub_4A8C81`, `sub_4A95CB`, `sub_427BF2` | 7.2k total | 151 distinct `sub_XXXXXX` names; 306 total occurrences |
| `src/OpenLoco/src/Map/Track/SubpositionData.cpp` | (static init) | 18.9k | Generated data table as C++ code |
| `src/OpenLoco/src/Ui/Windows/Vehicle.cpp` | `update()`, `onMouseUp()` | 5.2k | Monolithic window logic |

### Poor Naming / Inconsistent Patterns

- **306 occurrences** of `sub_XXXXXX` raw assembly addresses as function names across 151 distinct addresses (e.g., `sub_4A8DB7`, `sub_427122` in `VehicleHead.cpp`, `Routing.cpp`, `CompanyAi.cpp`).
- **Magic flags:** `ThoughtTypeFlags::unk7`, `unk112C5A6`, `unkStationFlags` in `CompanyAi.cpp:198,764,448`.
- **`gc_unk_34` through `gc_unk_70`** in `GameCommands.h:55-59` — unknown command IDs still exposed.
- **Widget constructors** have 6 overloads with different parameter orders (`Widget.h:120-180`).
- **`FormatArguments`** uses static thread-unsafe default buffers (`FormatArguments.hpp:60,70,78`).

### Error Handling / Validation Gaps

- **S5 load (`S5.cpp`):** Uses `std::memcpy` into fixed-size structs with only `assert`-level validation on sizes (lines 415, 638, 652, 666). No bounds checks on chunk sizes before `readChunk`.
- **ObjectManager (`ObjectManager.cpp`):** Validates checksum only *after* full object load (lines 403, 436-459); `malloc` + `reinterpret_cast` with no size ceiling (line 465).
- **Network packets (`Packet.h`):** `Packet::as<TKind, T>()` checks `dataSize >= sizeof(T)` but no upper bound on variable-length packets (chat `text[2048]`).
- **File/Memory streams (`FileStream.cpp`, `MemoryStream.cpp`):** Throw on short reads but no size limits on writes; `MemoryStream` grows unbounded (2x growth factor).

### Concurrency / Resource Management

- **Single-threaded game loop** (`App/Main.cpp:245-252`: `while (Input::processMessages()) { update(); }`). No worker threads.
- **Audio** runs on main thread via OpenAL (`AudioEngine.cpp`).
- **No RAII for SDL/OpenAL** — `Ui.cpp` manually calls `SDL_CreateWindow`/`SDL_DestroyWindow`, `AudioEngine.cpp` calls `alcOpenDevice`/`alcCloseDevice`.
- **`FormatArguments` static buffers** are not thread-safe (used from UI tooltips during render).

## 4. Performance

### Unnecessary I/O / Repeated Computation

- **S5 save/load:** Full game state `memcpy` (1.2 MB+) on every save/load (`S5.cpp:638,652,666`). No incremental/dirty-region saves.
- **TileManager reorganise:** `reorganise()` scans entire map (4096 tiles × 255 elements) on demand (`TileManagerTests.cpp:300`). Could be incremental.
- **Vehicle routing:** `Routing.cpp:1682` lines with repeated `sub_4A2AD7`/`sub_4A2A77` calls per tick per vehicle. No caching of pathfinding results.
- **Company AI:** `CompanyAi.cpp:7889` lines runs every tick for all companies; `aiThinkState0` iterates all stations/vehicles.

### Inefficient Data Structures

- **`ShortcutMap`** is `std::vector<ShortcutEntry>` with `std::lower_bound` (O(log n) insert/find but O(n) insert due to shift). Only ~50 shortcuts — fine, but `std::map` or `flat_map` would be cleaner.
- **`ObjectManager`** uses fixed-size `std::array<Object*, kCount>` per type (max 255 per type). No sparse storage for unloaded objects.
- **`TileElementEntry`** linked-list per tile with `kTileElementSize=32` byte payload. 1.05M elements preallocated. `reorganise` compacts but fragments.

### Excessive Allocations

- **`MemoryStream`** 2x growth factor + 4K page alignment (`MemoryStream.cpp:165`). Frequent reallocs during S5 chunk decode.
- **`SawyerStreamReader`** uses member `MemoryStream` `_decodeBuffer`/`_decodeBuffer2` reused per chunk — good.
- **Widget `textArgs`** `FormatArgumentsBuffer` (16 bytes) per widget — thousands per frame.

### TBB / `<execution>` Dependency

- **vcpkg.json:5** declares `benchmark` and `tbb` (via `libstdcxx-execution` feature).
- **CMakeLists.txt:42-46** detects libstdc++ and requires TBB for `<execution>`.
- **No code uses `std::execution::par` or TBB** (grepped entire tree). **Unused heavyweight dependency.**

## 8. Security and Reliability

### Unsafe Input Handling

| Location | Issue | Risk |
|---|---|---|
| `S5.cpp:415,638,652,666` | `memcpy` into fixed structs without size validation | Save file OOB read/write → RCE |
| `ObjectManager.cpp:465` | `malloc(data.size())` + `reinterpret_cast<Object*>` no max size | OGA file with huge `dataSize` → OOM / heap overflow |
| `Packet.h:103-107` | `RequestStateResponseChunk::data[kMaxPacketDataSize-14]` variable len; `size()` uses pointer arithmetic | Malformed packet → stack/info leak |
| `NetworkConnection.cpp:85` | `sendPacket(PacketKind, size_t, const void*)` no upper bound check beyond `assert` | Oversized send → buffer overflow |
| `FormatArguments.hpp:95` | `push<T>` allows any even-sized type; `reinterpret_cast` to `T*` | Type confusion if caller mismatches |

### Secret Exposure

- **No secrets in repo** (`.gitignore` covers `build/`, `vcpkg/`, `*.pdb`).
- **CI uses `ASSETS_SSH_KEY`** only on `OpenLoco/OpenLoco` repo — correct.

### Failure Scenarios / Inconsistent State

- **S5 load** throws on checksum failure (`S5.cpp:581-583`) but partial state may already be written to `file->gameState`/`tileElements`.
- **Object load** on checksum mismatch logs error but continues with `preLoadObj` (`ObjectManager.cpp:453-460`) — inconsistent object state possible.
- **Network** `close()` nulls `_server`/`_client` but in-flight packets may reference freed `NetworkConnection`.
- **GameCommand `doCommand`** returns `kFailure` (0x80000000) but callers often ignore return value.

- **12 modules** under `src/`: App (354 lines), Audio (739), Core (3041), Diagnostics (1040), Engine (389), Gfx (180), Math (899), OpenLoco (231,142), Platform (812), Resources (16), Utility (736), Version (103).

### Recommended Next Step

**Extend offline unit/regression tests around S5 save/load and Object parsing.**

**Why:** This is the single highest-leverage task. It simultaneously:
- Closes the **P0 security gaps** (validates bounds checking works)
- Enables **public CI determinism** (no longer dependent on private `LocomotionAssets`/`TestData`)
- Provides **regression safety** for the 231k-line OpenLoco monolith during future refactors
- Unblocks **save format versioning** (NSF) work by establishing round-trip test baseline

**Concrete deliverable:** A new test target `OpenLocoFuzzTests` (or `S5Tests`/`ObjectTests`) that:
- Fuzzes `S5::load()` with truncated/oversized/corrupted chunks (using libFuzzer or AFL++ via CMake)
- Fuzzes `ObjectManager::loadObject()` with malformed OGA headers/data
- Includes a small redistributable test save (`test.sv5`) for `simulate` + `compare` in public CI
- Runs in <30s on CI without external assets

This pays down the testing debt, secures the parsers, and creates the foundation for all subsequent refactoring.
